Local-first research-to-audio pipeline

Papers in.
Cited conversations out.

Drop in a research PDF. xCAST extracts it page by page, writes a two-voice script where every claim points back to its page, pauses for your review, then narrates, mixes, and captions the episode — on your own machine.

Start an episode
  • Page-level citations

Pipeline

Eight stages. Every one leaves a file you can inspect.

  1. IngestPDF upload, validated & queued
  2. ExtractPage text, headers stripped
  3. ChunkOverlapping, page-anchored
  4. RetrieveLocal · FAISS
  5. ScriptOllama · OpenRouter
  6. ReviewEdit, approve or reject
  7. VoiceQwen · Piper · Coqui · Minimax
  8. MixPacing, LUFS, captions

Dashed stages are optional and switched on per job or per deployment.

Why it's different

Built for people who have to trust what they hear.

Grounded, not guessed

Segments carry the source, page, and snippet that support them. When the paper doesn't say it, the script says so instead of inventing it.

p.3 p.7 p.12

Review before voice

Pause any job at the script. Rewrite lines, rename speakers, then approve — or reject with a note.

Stays on your machine

Local LLMs and local TTS. PDFs and outputs live in data/ unless you point storage at S3.

Paced for comprehension

Speaking rate and pauses adapt to math density and sentence length.

Swap any adapter

LLM, embeddings, vector store, queue, storage and TTS are ports — not rewrites.

A worker you can leave running

Retries with exponential backoff, a dead-letter queue for poison jobs, and idempotent submissions — on a local directory, a file, or Redis.

Outputs

One upload, a complete episode kit.

  • episode.mp3Normalized multi-voice mix
  • transcript.srtCaptions for any player
  • transcript.txtPlain-text transcript
  • script.mdReadable, cited script
  • script.jsonSegments + citations
  • audio_quality.jsonLoudness & QA report

          Quick start

          The studio talks to the API on this origin. Jobs only move once a worker is running.

          make bootstrap
make api      # http://localhost:8000
make worker   # in a second terminal

          Or bring up the full stack, including Redis and Ollama:

          docker compose up --build

          Data & privacy

          • Uploads are saved to data/jobs/<job_id>/; outputs to data/processed/<job_id>/, or S3 when configured.
          • If the server sets API_KEY, enter it under Connection. It is kept in memory for this tab only and sent as the x-api-key header — never in a URL or browser storage.
          • This browser remembers only recent job IDs and file names, so you can reopen them. Clear them from the Studio list anytime.
          • Purge old artifacts with python scripts/purge_stale_artifacts.py --max-age-days 14.
          • Web fonts load from Google Fonts. Your documents never do; offline, the UI falls back to system fonts.

          Troubleshooting

          Stuck on “Queued”
          No worker is picking up jobs. Start one with make worker and check that QUEUE_MODE matches the API.
          401 Unauthorized
          The server requires an API key. Open Connection in the top bar and enter it.
          413 or 415 on upload
          The file is larger than UPLOAD_MAX_BYTES or isn't a PDF.
          Failed after retries
          Check the worker logs. Common causes: Ollama not running, a model not pulled, or a TTS engine that isn't installed.
          Captions drift from audio
          SRT timings are estimated from word counts, so they are approximate.
